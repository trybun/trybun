# Toolchain – pnpm, TypeScript, Next.js, NestJS build, Vitest, ESLint

Non-obvious behaviour found when the monorepo was scaffolded (S0-01, October 2026). Decisions: [ADR 0002](../../docs/adr/0002-technology-stack.md), [ADR 0003](../../docs/adr/0003-module-system-and-server-bundling.md).

- **pnpm 12**: settings live in `pnpm-workspace.yaml`, not in `package.json`. A dependency with an install script that is not listed in `allowBuilds` fails the install (`ERR_PNPM_IGNORED_BUILDS`); approve or deny it with `pnpm approve-builds <pkg> '!<pkg>'`, which writes `allowBuilds`. `minimumReleaseAge: 10080` refuses versions younger than 7 days (Rule 10), so `pnpm add x@latest` may fail right after a release – pick the newest version older than 7 days. A security fix younger than 7 days (§2.10: no cooldown) goes to `minimumReleaseAgeExclude` pinned to the exact version (`body-parser@2.4.0`), with the GHSA in a comment; `pnpm update -r <pkg>` then updates a transitive dependency within its parents' ranges without an override. When the parent pins the vulnerable version exactly (`@nestjs/platform-express` pins `multer`), add a version-scoped entry to `overrides` in `pnpm-workspace.yaml` (`multer@2.4.0: 2.5.0`), so it stops matching once the parent moves on. `pnpm peers check` lists unmet peers.
- **The root `prepare` script also runs under `pnpm install --filter <pkg>...`** (pnpm 12.13, #438): the Dockerfiles' filtered installs run `scripts/install-git-hooks.js` as well. It does nothing there because the script finds no work tree: `.dockerignore` excludes `.git` and the slim Node image has no `git` (either alone is enough, and the script treats both cases as no work tree). A new root lifecycle script must tolerate a build context without `.git` or Git; `--ignore-scripts` skips it.
- **TypeScript 7** (native compiler) is not supported by `typescript-eslint` 8 (`<6.1.0`) and the NestJS 12 CLI (`~6.0.2`); stay on `~6.0` until they are. Dependabot ignores `typescript` majors; remove that `ignore` entry together with the upgrade.
- **`@types/node`** keeps the major of the Node.js runtime (`.node-version`): newer types accept APIs that fail at run time. Dependabot ignores its majors (#49 moved it ahead of the runtime); the major moves in the task that moves the runtime to the next LTS line (S0-18).
- **Next.js 16**:
  - an error thrown in `register()` of `instrumentation.ts` is only logged and the server keeps serving; `src/instrumentation-node.ts` exits the process on an invalid environment. Node-only code is imported only when `NEXT_RUNTIME === 'nodejs'`, otherwise the build warns about the Edge Runtime.
  - Next loads `.env` only from `apps/web`; `next.config.ts` loads the root `.env` with `loadEnvConfig(root, undefined, undefined, true)` – without `forceReload` the call returns Next's cached environment and loads nothing. `node --env-file…` does not work for `next`: Next copies the flag into `NODE_OPTIONS`, where Node rejects it.
  - the standalone `server.js` (16.4) creates its server with `http.createServer` and only reads `KEEP_ALIVE_TIMEOUT`: Node's `requestTimeout` of 5 minutes applies to every request through the BFF, uploads included, and has no setting (§13.3). The API sets its own (`platform/http/request-timeout.ts`).
  - `next dev` writes `apps/web/AGENTS.md` with a pointer to the bundled docs in `node_modules/next/dist/docs/` and re-creates it when removed; it is committed.
  - module `nodenext` with `.js` imports of `.ts` files works with Turbopack, including the internal packages.
  - `next/font/google` must be imported by exactly that name (the font loader transforms only that specifier), which `nodenext` cannot resolve without an extension; `next/link` and `next/image` are CommonJS, so TypeScript types their default import as the whole module (like `next-auth`). `apps/web/src/lib/next/next-modules.d.ts` declares the three extensionless names with the types of their implementations – import them without `.js`.
  - Tailwind CSS 4 needs `postcss.config.mjs` with `@tailwindcss/postcss`; `src/app/globals.css` imports `@trybun/ui/globals.css` and adds `@source '../'` for the classes of the application.
  - The Dockerfile of `web` copies `apps/web/public` next to the standalone server; the standalone output does not include it.
  - **History entries of the App Router** (S1-10, `lib/forms/use-unsaved-changes.ts`): Next.js 16.4 keeps `__NA` and its router tree in `history.state` of every entry and patches `pushState`/`replaceState` to copy them in; on `popstate` it restores the page from the entry's tree and *reloads the page* for a state without `__NA`. An entry of our own therefore carries a copy of the current state. Its listener is a plain `popstate` listener on `window`: a capture-phase listener on `window` runs before it and can `stopImmediatePropagation()` a traversal between two entries of the same URL (jsdom behaves the same). Every commit of the router (refresh, Server Action) `replaceState`s the current entry without custom keys, so a marker in the state can disappear – track the current entry by address and own bookkeeping, not by the marker alone. A link to a fragment (`#main`) pushes an entry with a `null` state (jsdom: `undefined`, and only after a task) and fires `popstate` – Next.js ignores a `null` state; compare addresses without the fragment. jsdom has no Navigation API and starts a test file with one entry, so a test of Back pushes an entry first.
- **NestJS CLI rspack builder**: needs `webpack-node-externals` and `tsconfig-paths-webpack-plugin` installed. Its default externals treat the `@trybun/*` workspace symlinks as npm packages; `apps/server/rspack.config.js` allowlists them (also for the root `node_modules`). Type-only imports from `@trybun/contracts` vanish from the bundle – check `dist/main.js` for inlined code, not for import statements. `nest start --env-file` fails without the file; the scripts use `--exec "node --env-file-if-exists=../../.env"`. `--exec` runs in a shell and the CLI appends `--enable-source-maps dist/main`; it stops the child with tree-kill before a restart, so `--exec "node … dist/worker.js & node …"` restarts the API and the Worker together.
- `NestFactory.create()` calls `process.abort()` on an initialization error by default; the entry points pass `abortOnError: false` so the configuration error is printed and the exit code is 1.
- **Vitest** transforms with esbuild, which emits no decorator metadata; NestJS tests need `unplugin-swc`.
- **Zod issues** through Standard Schema keep their Zod fields (`code`, `origin`), which the validation `exceptionFactory` maps to field error codes.
- **ESLint flat config** replaces the options of a rule in a later config object, so overrides of `no-restricted-imports` and `no-restricted-syntax` repeat the shared patterns (`restrictedImports()` in `@trybun/eslint-config`). `import-x/no-restricted-paths` resolves zones from `process.cwd()` unless `basePath` is set – the app configs pass their folder as `root`. `tseslint.configs.disableTypeChecked` also turns off `@typescript-eslint/naming-convention`. `eslint-plugin-import-x` needs `import-x/parsers` and `import-x/extensions` for `.ts` files, otherwise it cannot read dependencies and `import-x/no-cycle` silently finds no cycle.
- **CommonJS packages under `nodenext`** (S0-05): for a CommonJS module compiled from ES modules (`exports.default` with `__esModule`, e.g. `next-auth`), TypeScript types the default import as the whole module, while Turbopack resolves it to `exports.default` – `X.default()` type-checks and fails at run time. `apps/web/src/lib/auth/next-auth.ts` resolves both cases.
- **`next build` prerenders** pages that call no request API before reading the environment, and fails on the missing runtime variables; `getSession()` awaits `connection()` first.
- **MSW in integration tests** intercepts supertest's requests to the application under test too; `apps/server/test/msw/server.ts` passes loopback requests through.
- **OpenAPI document** (S0-08): `apps/server/src/platform/http/openapi.spec.ts` compares the document of the whole `ApiModule` (created with `TEST_ENV`, no database needed) with the committed `apps/server/openapi.json` through `toMatchFileSnapshot`; `pnpm api:generate` runs it with `--update` and then `openapi-typescript` into `apps/web/src/lib/api-client/schema.d.ts`. `pnpm lint` of `web` runs `openapi-typescript --check`, and `apps/web/turbo.json` lists the document as an input of its lint. Both files are excluded from Prettier, `schema.d.ts` also from ESLint.
- `fetch` with a streamed request body needs `duplex: 'half'` in Node.js, which the DOM type of `RequestInit` does not declare: type the init object as `RequestInit & { duplex: 'half' }`.
- **Turborepo 2** runs tasks in strict environment mode: variables not declared in `turbo.json` are removed, so `dev` passes `TRYBUN_*` through (`passThroughEnv`).
- **Vitest 5 coverage** (S0-02): the root `vitest.config.ts` runs every package config as a project (`test.projects`) for `pnpm test:coverage`; only the root `coverage` options apply, and a project needs a unique `test.name` (two configs in `apps/server`). Glob thresholds (`'apps/web/src/**': { lines: 70 }`) are checked per glob, and the global thresholds would cover *all* files including the globbed ones – so the config sets only per-package globs. A file never imported by a test is reported with 0 % (a schema-only module needs a test that imports it). `vitest run --project scripts` does not start the global set-up (containers) of the other projects.
- **Testcontainers 12** pulls `ssh2`, `cpu-features` and `protobufjs` with install scripts; none is needed (denied in `allowBuilds`). Containers are started once per run in `globalSetup` and passed to tests with `project.provide()` / `inject()`; images are pinned to a digest.
- Integration test files run in parallel against **one** PostgreSQL: a running outbox publisher takes the pending events of every file and publishes them to its own queues (or none). All tests with a running publisher live in `platform/outbox/outbox.integration.spec.ts`.
- **Serialized integration tests under coverage load** (#232): a test whose requests queue on one row lock (the 50 concurrent ticket creations on the counter) takes the sum of every lock holder's queries – about 1 s alone, 3.7 s to over 5 s in a full `pnpm test:coverage`, where every query slows down several times. Give such a test an explicit `{ timeout }` named after its workload instead of the default 5 s; measure the duration of one test with `pnpm test:coverage --reporter=json --outputFile=…`.
- **Large buffers in Vitest**: `expect(buffer).toEqual(otherBuffer)` compares a 12 MB `Buffer` element by element and takes about a minute; compare with `expect(buffer.equals(other)).toBe(true)` (S1-08).
- **`clamscan` 2.4** (S1-08): `scanStream` resolves `isInfected: null` (not a rejection) when clamd's reply is neither `OK` nor `FOUND`, e.g. `COMMAND READ TIMED OUT`, although `@types/clamscan` types it `boolean`; its `timeout` is an idle timeout of the socket, not of the scan; it applies no backpressure (input `data` events go straight to the socket) and logs socket errors with `console.error`. `ping()` resolves with the open socket, which the caller must `end()`.
- **`sharp` 0.35** (S1-08): no install script (no `allowBuilds` entry); the prebuilt libvips comes as optional `@img/sharp-*` packages, so the `trixie-slim` server image needs nothing extra (verified with `docker build` and a JPEG encode inside the image). `metadata()` without `animated` reports the height of **one** frame plus `pages`; with `animated: true`, `height` is the total of all frames, and `limitInputPixels` then counts every frame (also in `metadata()`). Test fixtures: GPS EXIF through `withExif({ IFD3: { GPSLatitude: … } })` (the `Orientation` key of `IFD0` is ignored there) and the orientation in a second pass, `sharp(jpeg).withMetadata({ orientation: 6 })`, which keeps the GPS IFD; an animated GIF from `sharp(frames, { join: { animated: true } })`. A small PNG with huge dimensions is cheaper written by hand (IHDR plus a deflated IDAT of zero rows) than created by sharp, which would allocate the full raster.
- **MSW 3** renamed the `listen()` option `onUnhandledRequest` to `onUnhandledFrame`; the old name is ignored silently (outside type checking), so unhandled requests reach the network.
- **pnpm 12 audit**: accepted advisories without a fix go to `auditConfig.ignoreGhsas` in `pnpm-workspace.yaml` with the reason (§2.10); `pnpm audit` then reports them as ignored and exits 0. CI's audit blocks only high and critical; moderate and low advisories on `main` are reported by the daily `advisory-audit.yml` through the tracking issue *Vulnerability advisories on main* (opened, reopened, closed by the workflow – fix the advisory or accept it in `ignoreGhsas`, never close the issue by hand to silence it). The same issue lists *Stale exceptions*: `minimumReleaseAgeExclude` entries past the cooldown or no longer in the lockfile, `ignoreGhsas` entries whose advisory gained a fix or was withdrawn, and `overrides` no dependency needs – remove them (for a patched GHSA, fix the dependency first). pnpm 12.13 applies an `overrides` key `name@1.2.3` to every dependent whose declared range **includes** 1.2.3 (`^10.0.0` too, not only an exact pin), so a key is needed while any dependent's range includes it. `pnpm list -r --depth Infinity --lockfile-only --json` reads the lockfile's tree without `node_modules` (workspace projects nest as `link:` entries); `pnpm why` has no lockfile-only mode. `pnpm config list --json` shows the effective settings: `auditConfig.ignoreGhsas` appears as `audit.ignore`. `pnpm audit --json` counts ignored advisories in `metadata.vulnerabilities` but leaves them out of `advisories`, and on an error prints nothing to standard output. An override across a major (minimatch 10 → 11, glob 10/13 → 14, #324) needs the consumers' calls checked first: minimatch 11 dropped `makeRe` (a regex-free matcher), which `eslint-plugin-import-x` before 4.18 imports, so ESLint fails to load with `does not provide an export named 'makeRe'`.

- **TanStack Query polling in Vitest** (S1-08): `refetchInterval` is never scheduled when `isServer` is true (`typeof window === 'undefined'`), so a test of a polling `queryOptions` with a `QueryObserver` and fake timers needs `// @vitest-environment jsdom`; then `vi.advanceTimersByTimeAsync()` drives the polls. jsdom has no `document.execCommand`: a component test that drops files into the GFM editor defines it as `() => false`, so the editor takes its fallback without undo.
- **TanStack Query: data of the rows of a page** (#357): a query per row multiplies every later read, not only the first – `invalidateQueries` refetches each active query of the prefix, and so does a window-focus refetch after `staleTime`. Read and cache such data once per page, keyed by **all** IDs of the page (not only the rows that need it: a key built from a filtered subset changes when a row stops qualifying, e.g. after revoking an account's last invitation, and the refetch of the list then starts a second read). Each row observes the page query with `select`. `queryClient.fetchQuery`/`prefetchQuery` default to `retry: false` (`@tanstack/query-core` `queryClient.js`) unless `retry` is set – also through `defaultOptions` – and observers in the browser to 3 retries (1 s, 2 s, 4 s), a `4xx` included. Since #427 the browser client's default `retryUnlessRefused` never retries a `4xx`; it is set in `BROWSER_QUERY_CLIENT_CONFIG` only, not in the shared `QUERY_CLIENT_CONFIG`, as a `retry` there would make every prefetch of the server retry too; the two server reads whose failure fails the page (`getTicketPage`, `getPortalProject`) pass it themselves, as they retried through their query options before. It tells a refusal by `instanceof ApiError` from `lib/errors/api-error-class.ts`, a module without Zod: `api-error.ts` imports the Problem Details schema, and the query provider of the root layout is in the first load of the shell (`scripts/check-first-load.ts`).
- **A held lazy chunk in a component test** (#326, `lazy-add-member-dialog.spec.tsx`): a `vi.mock` factory that awaits a test-controlled promise and then returns `importOriginal()` still has to transform the whole real module graph after the test releases it. Under a parallel `pnpm test` run that took longer than the 1 s of `waitFor`, so the test failed at random. Release the chunk and `await import('./the-module.js')` inside the same `act` – the mocked module resolves only after `importOriginal()` – and keep `waitFor` for React's re-render only. Never raise the `waitFor` timeout instead.
- **Typing long text in a component test** (#319, `inviting-flows.spec.tsx`): `userEvent.type` fires five events per character and the form re-renders on each one; for an e-mail address that took about 60 % of an `InviteDialog` test (~250 ms of ~440 ms with coverage, alone), and a loaded `pnpm test:coverage` pushed the test past 5 s. `userEvent.setup({ delay: null })` does not help (the cost is the events, not the pauses). When the test is not about per-key behaviour, `events.click(field)` then `events.paste(text)` enters the value in one input event (~30 ms).
- **Processes and process groups in POSIX `sh`** (#352, 2026-11-15, `.ai/scripts/test-env-*.sh`): `sh` is dash on Ubuntu, and dash's `kill -0 -- -PGID` fails with "Illegal number: -" while `kill -- -PGID` works – test a group with `kill -0 "-$pid"` (no `--`), which bash accepts too. `kill -0 PID` also fails with EPERM for an existing process of another user (PID 1 as a non-root user), so it does not tell whether a process exists; `ps -p PID` does. `setsid sh -c … &` keeps `$!` as the group's PID only when the caller is not a group leader (a script run by `sh`); from an interactive shell `setsid` forks and `$!` is a PID that already exited. Signals (#383, 2026-11-20, checked under dash): without job control an asynchronous command (`cmd &`) starts with SIGINT and SIGQUIT ignored (`SigIgn` 0x6 in `/proc/<pid>/status`), and a signal ignored on entry cannot be trapped – forward `SIGTERM` to a background child, never `SIGINT`. Killing the shell of a background step (`sh -c "…" &`) leaves its children running – start a step that must be stoppable with `setsid … & wait $!` and stop its group (`kill -- -PID`). A trap runs only after the current foreground command has ended, but a trapped signal interrupts `wait` at once – wait in loops with `sleep N & wait $!`, not `sleep N`. A closed terminal can deliver SIGHUP more than once (QA of #417, 2026-11-21: closing a cezar terminal tab left the environment running): the second signal killed the `sed` a trap handler read its state with, so the handler took the wrong branch. A handler that decides or cleans up therefore starts with `trap '' HUP INT TERM`, and the commands it runs inherit the ignored signals. A test that signals the group every few ms for 0.5 s reproduces it.
- **Next.js: expected API errors of a Server Component** (#356): `prefetchQuery` never throws, so `getQueryData()` after it is `undefined` for **every** failure – deciding "no permission → `notFound()`" on it turns a `429` into a 404. Read with `fetchQuery` (throws, `retry: false`) or check `getQueryState().error`. Do not count on `error.tsx` for a known code: in production Next.js 16 forwards Server Component errors as a generic `Error` with only a `digest` (`node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/error.md`), so the page renders the message itself (`RateLimitedNotice`, through `readOrRateLimited()`, and `AccountShell` for the whole block), as the Next.js guide on expected errors says (`01-getting-started/10-error-handling.md`). `Date.parse` reads `-5` and `1.5` as dates; `retryAfterSecondsOf()` parses the three HTTP-date formats itself. Checked with a minimal Next.js 16.4.5 app: a layout that does not render `children` still runs its page in parallel; an error the page throws is only logged (`⨯ Error … digest`) and the response stays `200` with the layout's content – why `AccountShell` may replace the page by a notice (`401`, `429`). `error.tsx` (#382, 2026-11-19): Next.js 16.4 passes `retry()` – fetches the Server Components again and renders the segment – besides `reset()`, which only clears the error state, so **Try again** uses `retry`. An `error.tsx` does not wrap the `layout.tsx` of its own segment: `(team)/error.tsx` stays inside the shell, and an error of `AccountShell` itself reaches `app/error.tsx`, which renders under the provider of the root layout only – its texts (`errorPage`, and `app` for the brand of `PublicHeader`) are in the `root` client namespaces; `app/error.spec.tsx` renders each `error.tsx` with the messages of the provider above it (`pickClientMessages`), so a namespace missing there fails. No `global-error.tsx` on purpose (§18.5). `not-found.tsx` (#401, 2026-11-20): Next.js 16.4 reads the metadata of a `not-found.tsx` only when the *metadata* resolution hits a not-found – an unmatched address (root `app/not-found.tsx`) or `generateMetadata` calling `notFound()` (`dist/esm/lib/metadata/metadata.js`, `createMetadataComponents`); a page that calls `notFound()` while rendering keeps the metadata of its layouts, so `generateMetadata` of `(team)/not-found.tsx` is never used. Its own 404 page sets the title as a `<title>` element (`client/components/http-access-fallback/error-fallback.js`), which React hoists before the streamed metadata title: on a page load the element wins, but after a client-side navigation to a 404 page or a `router.refresh()` on it (language switch) the metadata title mounts after the element and the tab shows the layout title ("Trybun") – checked in the browser against a production build (QA of PR #403). Fix (#404, 2026-11-20): every `not-found.tsx` exports `generateMetadata` and `NotFoundNotice` renders no element; every page that can call `notFound()` exports a `generateMetadata` that performs the page's read (`metadataAfterRead()`), memoized with React `cache()` for one API read per request ([ADR 0014](../../docs/adr/0014-not-found-title-through-metadata.md)); `app/page-titles.spec.ts` (since #407, replacing `not-found-metadata.spec.ts`) fails for a `page.tsx` without `generateMetadata`. The not-found convention takes the metadata of the deepest segment with a `not-found.tsx` and of the layouts above it; the page's own `generateMetadata` is not used then (`resolve-metadata.js`, `collectMetadata`). React `cache()` memoizes only under the `react-server` condition: in Vitest it calls the function every time, so the specs check that the page and its metadata call the same read, not that it runs once. A Client Component that calls `notFound()` keeps the title of the page, so a `404` of a query in the browser refreshes the route (`useNotFoundOnServer()`) instead. For `notFound()` inside the shell, the server HTML holds neither the not-found texts nor the element: both arrive in the RSC payload and render on hydration (QA of PR #403). Tab titles of every page (#407, 2026-11-20): never `title.template` – `resolveTitleTemplate()` (`dist/esm/lib/metadata/resolvers/resolve-title.js`) runs `template.replace(/%s/g, title)`, so `$&`, `` $` `` and `$'` in a ticket or project name are replacement patterns ("Price $& and $' x" became "Price %s and  – Trybun x – Trybun"), `accumulateMetadata()` does not apply the leaf layout's template (so not to `app/not-found.tsx`), and a plain string title in a nested layout resets the template below it; `pageTitle()` of `features/app-shell` builds `title.absolute` instead ([ADR 0015](../../docs/adr/0015-page-titles-through-absolute-metadata.md)). next-intl inserts message arguments as typed (`{`, `<b>`, `%s` stay literal), so record values go through `app.titlePart` safely.
- **`window.location.reload` cannot be spied on in jsdom** (#433): the members of `Location` are unforgeable (`configurable: false`), so `vi.spyOn(window.location, 'reload')` throws "Cannot redefine property". Test the callback one level up (`onReload` of `RateLimitedMessage`) and only the rendered control in the component that calls `reload()` (`query-error-alert.spec.tsx`). `window.history.replaceState(null, '', '/path#fragment')` sets the address, fragment included, for a component that reads `location.hash`; reset it in `afterEach`.
- **A link cannot reload an address with a fragment** (#433, HTML navigation): following `<a href>` to the current URL with a fragment only scrolls to the fragment (fragment navigation), and a link without the fragment drops it – the token of an invitation link (ADR 0009). A **Reload page** there is a button calling `location.reload()` (`RateLimitedAlert`).
