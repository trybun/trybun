# Toolchain – pnpm, TypeScript, Next.js, NestJS build, Vitest, ESLint

Non-obvious behaviour found when the monorepo was scaffolded (S0-01, October 2026). Decisions: [ADR 0002](../../docs/adr/0002-technology-stack.md), [ADR 0003](../../docs/adr/0003-module-system-and-server-bundling.md).

- **pnpm 12**: settings live in `pnpm-workspace.yaml`, not in `package.json`. A dependency with an install script that is not listed in `allowBuilds` fails the install (`ERR_PNPM_IGNORED_BUILDS`); approve or deny it with `pnpm approve-builds <pkg> '!<pkg>'`, which writes `allowBuilds`. `minimumReleaseAge: 10080` refuses versions younger than 7 days (Rule 10), so `pnpm add x@latest` may fail right after a release – pick the newest version older than 7 days. `pnpm peers check` lists unmet peers.
- **TypeScript 7** (native compiler) is not supported by `typescript-eslint` 8 (`<6.1.0`) and the NestJS 12 CLI (`~6.0.2`); stay on `~6.0` until they are.
- **Next.js 16**:
  - an error thrown in `register()` of `instrumentation.ts` is only logged and the server keeps serving; `src/instrumentation-node.ts` exits the process on an invalid environment. Node-only code is imported only when `NEXT_RUNTIME === 'nodejs'`, otherwise the build warns about the Edge Runtime.
  - Next loads `.env` only from `apps/web`; `next.config.ts` loads the root `.env` with `loadEnvConfig(root, undefined, undefined, true)` – without `forceReload` the call returns Next's cached environment and loads nothing. `node --env-file…` does not work for `next`: Next copies the flag into `NODE_OPTIONS`, where Node rejects it.
  - `next dev` writes `apps/web/AGENTS.md` with a pointer to the bundled docs in `node_modules/next/dist/docs/` and re-creates it when removed; it is committed.
  - module `nodenext` with `.js` imports of `.ts` files works with Turbopack, including the internal packages.
- **NestJS CLI rspack builder**: needs `webpack-node-externals` and `tsconfig-paths-webpack-plugin` installed. Its default externals treat the `@trybun/*` workspace symlinks as npm packages; `apps/server/rspack.config.js` allowlists them (also for the root `node_modules`). Type-only imports from `@trybun/contracts` vanish from the bundle – check `dist/main.js` for inlined code, not for import statements. `nest start --env-file` fails without the file; the scripts use `--exec "node --env-file-if-exists=../../.env"`. `--exec` runs in a shell and the CLI appends `--enable-source-maps dist/main`; it stops the child with tree-kill before a restart, so `--exec "node … dist/worker.js & node …"` restarts the API and the Worker together.
- `NestFactory.create()` calls `process.abort()` on an initialization error by default; the entry points pass `abortOnError: false` so the configuration error is printed and the exit code is 1.
- **Vitest** transforms with esbuild, which emits no decorator metadata; NestJS tests need `unplugin-swc`.
- **Zod issues** through Standard Schema keep their Zod fields (`code`, `origin`), which the validation `exceptionFactory` maps to field error codes.
- **ESLint flat config** replaces the options of a rule in a later config object, so overrides of `no-restricted-imports` and `no-restricted-syntax` repeat the shared patterns (`restrictedImports()` in `@trybun/eslint-config`). `import-x/no-restricted-paths` resolves zones from `process.cwd()` unless `basePath` is set – the app configs pass their folder as `root`. `tseslint.configs.disableTypeChecked` also turns off `@typescript-eslint/naming-convention`. `eslint-plugin-import-x` needs `import-x/parsers` and `import-x/extensions` for `.ts` files, otherwise it cannot read dependencies and `import-x/no-cycle` silently finds no cycle.
- **CommonJS packages under `nodenext`** (S0-05): for a CommonJS module compiled from ES modules (`exports.default` with `__esModule`, e.g. `next-auth`), TypeScript types the default import as the whole module, while Turbopack resolves it to `exports.default` – `X.default()` type-checks and fails at run time. `apps/web/src/lib/auth/next-auth.ts` resolves both cases.
- **`next build` prerenders** pages that call no request API before reading the environment, and fails on the missing runtime variables; `getSession()` awaits `connection()` first.
- **MSW in integration tests** intercepts supertest's requests to the application under test too; `apps/server/test/msw/server.ts` passes loopback requests through.
- **Turborepo 2** runs tasks in strict environment mode: variables not declared in `turbo.json` are removed, so `dev` passes `TRYBUN_*` through (`passThroughEnv`).
- **Vitest 5 coverage** (S0-02): the root `vitest.config.ts` runs every package config as a project (`test.projects`) for `pnpm test:coverage`; only the root `coverage` options apply, and a project needs a unique `test.name` (two configs in `apps/server`). Glob thresholds (`'apps/web/src/**': { lines: 70 }`) are checked per glob, and the global thresholds would cover *all* files including the globbed ones – so the config sets only per-package globs. A file never imported by a test is reported with 0 % (a schema-only module needs a test that imports it). `vitest run --project scripts` does not start the global set-up (containers) of the other projects.
- **Testcontainers 12** pulls `ssh2`, `cpu-features` and `protobufjs` with install scripts; none is needed (denied in `allowBuilds`). Containers are started once per run in `globalSetup` and passed to tests with `project.provide()` / `inject()`; images are pinned to a digest.
- **MSW 3** renamed the `listen()` option `onUnhandledRequest` to `onUnhandledFrame`; the old name is ignored silently (outside type checking), so unhandled requests reach the network.
- **pnpm 12 audit**: accepted advisories without a fix go to `auditConfig.ignoreGhsas` in `pnpm-workspace.yaml` with the reason (§2.10); `pnpm audit` then reports them as ignored and exits 0.
- **lychee** (link check): `include_fragments` takes `"anchor-only"`/`"full"`, not a boolean, in `lychee.toml`; `.claude/skills` is a symlink to `.ai/skills` and is excluded to avoid duplicate reports.
