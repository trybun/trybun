# TanStack Query – mutations and infinite queries: callbacks, unmounting, offline, failed pages

Non-obvious behaviour of TanStack Query 5 found while fixing #368 (PR #387). Patterns: [§18.5](../../docs/spec/18-code-patterns.md).

- **Per-call callbacks of `mutate` never run for an unmounted component.** `mutate(variables, { onSuccess, onError })` calls them only while the observer still has listeners (`mutationObserver.ts`, `hasListeners()`). The hook-level `onSettled` runs first and is awaited, so an invalidation there (`invalidateQueries`) can refresh a list that removes the very component before the per-call `onError` runs. The toast of that refusal is then silently lost. Typical case: the last item of a list whose wrapper renders nothing when the list is empty. Use `mutateAsync(variables).then(onSuccess, onError)` for feedback that must survive the component, as `pending-invitation-list.tsx` does. A component test only catches it when another query of the invalidation is still running after the list has gone (`inviting-flows.spec.tsx`, `ProjectInvitations`).
- **Offline pauses mutations instead of failing them.** With the default `networkMode: 'online'`, a mutation started while `navigator.onLine` is false waits and is sent once the browser is back online. The DevTools Offline switch (or `context.setOffline`) therefore never reaches an error path. To test an error, block or abort the request URL instead (Playwright `page.route(…).abort()`; Chrome and Edge DevTools **Request conditions** with a URLPattern such as `http://localhost:3000/api/v1/invitations/*/revocation`).
- **A failed later page sets `isError` and keeps `data`** (found in #434, TanStack Query 5.107). After `fetchNextPage()` fails, an infinite query has `status: 'error'`, `isError: true`, `isFetchNextPageError: true` and all the pages loaded before; a refetch error keeps `data` too (`isRefetchError`). A list that checks `isError` before its rows therefore drops what it already showed. Replace the rows only on `isLoadingError` (error without data) and show the other errors above **Load more** ([§18.5](../../docs/spec/18-code-patterns.md)). In a server-HTML test seed that state with `seedFailedLaterPage()` of `apps/web/test/query-state.ts`; in jsdom press **Load more** against `laterPagesFail()` of `test/dom/fake-api-client.ts` instead, because a mounted query in `error` reads again (`retryOnMount`).
