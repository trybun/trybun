# Process rules for agents

Where the rules of the delivery process live and how they relate to the installed `om-*` skills. Process: [`SDLC.md`](../../SDLC.md); agent rules: [`AGENTS.md`](../../AGENTS.md).

- **Process rules go to `SDLC.md`, and to `AGENTS.md` for agents – never into `.ai/skills/om-*` overrides** (#394, 2026-11-19): the rules are for agents, so that they do not start the next step on their own initiative, while the maintainer may run a skill against a rule deliberately – for example `om-auto-implement-spec` on a specification that is not merged yet – and a skill override would block that. The same rule in RckikSystem3 (#494, PR #495) first came with overrides of `om-auto-implement-spec`, `om-auto-fix-issue` and `om-spec-writing`, and the maintainer removed them. In review, a difference between an `om-*` skill and a process rule is therefore not a finding to fix with a skill override.
- **"Specification before implementation"** (#394) is the first such rule: a feature with a change specification is implemented only after its specification PR is merged to `main`. It was written after the feature route of `om-auto-fix-issue` went from the specification PR #392 straight to the implementation PR #393 for #374, before the maintainer had accepted the specification and its autonomous defaults. In your own runs, stop the feature route at the open specification PR; when the maintainer runs a skill deliberately, do what they asked.
- **An issue that changes only process documents fits neither route of `om-auto-fix-issue`** (#394, 2026-11-19): the bug route's gate `om-verify-in-repo` stops on it as not a defect, and the feature route writes a change specification that such an issue does not need (`.ai/specs/README.md`: documentation-only changes use none). #394 was delivered by hand along the same mechanics: the claim of the issue (lock ref, claim comment, `in-progress`), the edit in the task's worktree, `om-open-pr {issue} documentation --handoff om-auto-review-pr`, then `om-auto-review-pr {pr} --autofix`, and the release of the PR lock (`ci-monitoring` while CI runs). Follow the same path for the next one; don't add a skill override for it (entry above).
- **Read the research before researching again** (2026-11-27): the rule is in `AGENTS.md` ("Where things are", `.ai/specs/research/`). It was added because a session repeated part of the market benchmark of 2026-11-09 without looking there (#571).
